# 2026-10-08: Handoff, start here

First handoff for gama's working docs. It says where gama stands, what was
checked while the docs were written, and what is open.

## Where things stand

`main`, no uncommitted code changes (this `docs/` folder is new). `uv run pytest`:
**10 passed** (run 2026-10-08). About 1,240 lines of Python, 218 of them tests.

What gama does today (the [README](../../README.md) has the commands):

| Command | What |
| --- | --- |
| `checkpoint` | memory + raw screenshot + registers from the running DOSBox, filed in the Evi vault and decoded |
| `ingest`, `index`, `rebuild`, `status` | add dumps, decode new ones, decode everything again, count |
| `sql` | run SQL on the derived database |
| `filemap` | map file offsets to RAM addresses from the fork's file-call log |
| `surveyor` | list the Surveyor's hover texts and mouse positions from `hits.jsonl`; `--check` marks each as agreeing or conflicting with the tile rules |
| `resources` | the Surveyor's City Resources for a tile, from a dump or save |

The signature files for the fork are in [`signatures/mom/`](../../signatures/mom)
(`cities`, `surveyor`, `wizard`, `world`).

- Keep it game-agnostic where you can: the code that speaks to the fork and the
  vault shouldn't know about Master of Magic; `layout.py`, `decode.py` and the
  signature files may.
- `uv run pytest` before calling anything done. Synthetic dumps in tests only.
- Cross-repo: the fork's formats are described in its
  [`docs/apocrypha/reference/`](https://github.com/ApocryphaCipher/dosbox-staging/tree/apocrypha/research/docs/apocrypha/reference).
